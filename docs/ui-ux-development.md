## 2. 핵심 사용자 흐름

### 2.1. 문서 등록 및 분석

```
문서 목록
→ 파일 선택/업로드
→ 입력값 확인
→ 처리 시작
→ OCR 및 구조 분석 진행 상태 확인
→ 분석 결과 확인
→ 오류 수정 또는 다음 단계 이동
```

### 2.2. 인수인계서 생성

```
분석 완료 문서 선택
→ 생성 조건 입력
→ 인수인계서 생성
→ 내용과 원문 근거 비교
→ 검토 필요 항목 수정
→ 저장/확정
```

### 2.3. 통합 작성 흐름

전체 작업은 사용자가 현재 위치와 남은 단계를 바로 이해할 수 있도록 상단 단계 표시기(Stepper)를 사용하는 4단계 마법사 형태로 구성한다.

```text
1. 문서 입력
→ 2. 목차 구성 및 내용 보완
→ 3. 문서 서식 설정 및 PDF 생성
→ 4. 평가 문항 생성 및 확인
```

- 각 단계는 이전/다음 이동과 임시 저장을 지원한다.
- 사용자가 입력한 값과 AI가 문서에서 추출하거나 생성한 값을 시각적으로 구분한다.
- 필수 입력이 누락된 경우 해당 항목과 단계에 함께 표시하고, 오류를 수정하기 전에는 다음 단계로 이동하지 못하게 한다.
- OCR, 목차 구성, PDF 생성, 평가 문항 생성처럼 시간이 걸리는 작업은 진행률과 현재 처리 내용을 보여준다.
- 이전 단계로 돌아가 내용을 수정하면 영향을 받는 생성 결과를 알려주고 재생성 여부를 확인한다.
- 평가 문항이 필요하지 않은 사용자는 3단계에서 PDF를 내려받고 작업을 종료할 수 있다.

#### 2.3.1. 1단계: 문서 파일 입력

인수인계서 작성의 근거가 될 문서 파일을 등록하고 분석 대상을 확정하는 화면이다.

| 구분 | 요구사항 |
|---|---|
| 입력 | 드래그 앤 드롭 또는 파일 선택으로 인수인계 관련 문서 등록 |
| 지원 형식 | 1차 MVP는 스캔 PDF를 기본 대상으로 하며, 향후 DOCX/XLSX/TXT로 확장 |
| 파일 목록 | 파일명, 형식, 크기, 페이지 수, 업로드·분석 상태, 삭제 동작 표시 |
| 처리 상태 | 업로드, OCR, 구조 분석의 진행 상태를 단계별로 표시 |
| 검토 | 분석 실패, 중복 파일, 낮은 OCR 신뢰도, 지원하지 않는 형식을 구분하여 안내 |
| 완료 조건 | 한 개 이상의 문서가 정상 분석되고 사용자가 사용할 문서를 선택한 상태 |

주요 화면 구성은 파일 업로드 영역, 등록 문서 목록, 처리 상태 패널, `분석 시작` 및 `다음: 목차 구성` 버튼으로 한다.

#### 2.3.2. 2단계: 목차 구성 및 세부 내용 보완

분석된 문서들을 하나의 인수인계서 구조로 통합하고, 문서만으로 확인할 수 없는 필수 내용을 사용자에게 입력받는 핵심 편집 화면이다.

| 구분 | 요구사항 |
|---|---|
| 목차 초안 | 여러 문서의 제목과 섹션을 분석해 계층형 목차를 자동 구성 |
| 목차 편집 | 항목 추가·삭제·이름 변경, 드래그 앤 드롭 순서 변경, 상하위 단계 조정 지원 |
| 내용 편집 | 선택한 목차 항목의 본문, 표, 체크리스트, 주의사항을 편집 |
| 보완 입력 | 담당자, 업무 목적, 선행 조건, 업무 절차, 연락처, 주의사항 등 부족한 필드를 입력 폼으로 제시 |
| 출처 확인 | 자동 생성 내용에 원본 파일명과 페이지를 표시하고 원문과 비교 가능하게 구성 |
| 상태 표시 | `완료`, `입력 필요`, `검토 필요`, `근거 부족` 상태를 목차 항목별로 표시 |
| 완료 조건 | 필수 항목 입력과 검토가 끝나고 모든 목차 항목이 PDF 생성 가능한 상태 |

데스크톱에서는 왼쪽에 목차 트리, 가운데에 내용 편집기, 오른쪽에 원문 근거 및 입력 필요 항목을 배치한 3열 레이아웃을 기본으로 한다. 사용자가 직접 입력한 값은 `사용자 입력`, AI가 제안한 값은 `AI 제안` 배지로 구분한다.

#### 2.3.3. 3단계: 문서 서식 설정 및 PDF 생성

확정한 인수인계 내용을 미리 보면서 문서의 시각적 서식을 설정하고 최종 PDF를 만드는 화면이다.

| 구분 | 요구사항 |
|---|---|
| 서식 프리셋 | 기본, 간결형, 보고서형 등 재사용 가능한 서식 선택 |
| 글꼴 | 본문·제목 글꼴, 크기, 굵기, 줄 간격 설정 |
| 레이아웃 | 용지 크기, 세로/가로 방향, 여백, 단/표 배치 설정 |
| 머리말/꼬리말 | 문서명, 조직명, 작성일, 보안 등급 등의 표시 여부 설정 |
| 페이지 번호 | 표시 여부, 위치, 시작 번호, 표기 형식 설정 |
| 미리보기 | 설정 변경 결과를 실제 페이지 단위로 즉시 확인하고 확대·축소 및 페이지 이동 지원 |
| 출력 | `PDF 생성`, 생성 진행 상태, 오류 안내, 최종 파일 미리보기 및 다운로드 제공 |
| 완료 조건 | PDF 생성이 성공하고 사용자가 결과를 확인한 상태 |

서식 패널은 왼쪽, 페이지 미리보기는 가운데에 배치한다. 설정값은 자동 저장하며, PDF 생성 전 페이지 넘침, 잘린 표, 빈 페이지와 같은 레이아웃 경고를 보여준다.

#### 2.3.4. 4단계: 인수인계 평가 문항 생성

사용자가 평가 생성을 선택한 경우 확정된 인수인계서 내용을 근거로 이해도 확인 문제를 생성하고 검토하는 화면이다.

| 구분 | 요구사항 |
|---|---|
| 시작 선택 | 3단계 완료 후 `평가 문항 만들기` 또는 `PDF만 완료` 중 선택 |
| 생성 조건 | 문항 수, 문제 유형, 난이도, 평가 범위, 합격 기준 설정 |
| 문제 유형 | 객관식, 단답형, 서술형, 업무 절차 순서형 지원 검토 |
| 생성 결과 | 문제, 선택지, 정답, 해설, 난이도, 평가 기준(Rubric), 근거 페이지 표시 |
| 편집 | 문항 수정·삭제·재생성, 순서 변경, 문항별 사용 여부 선택 |
| 품질 검토 | 중복 문항, 근거 부족, 모호한 정답, 난이도 편중을 경고 |
| 출력 | 평가 미리보기, 평가 문항 확정 및 향후 응시 화면으로 이동 |
| 완료 조건 | 사용할 문항을 검토·확정했거나 평가 생성을 건너뛴 상태 |

평가 문항은 카드 또는 목록으로 표시하고, 각 문항에서 정답과 해설을 접고 펼칠 수 있게 한다. AI가 만든 문항은 검토 전에는 바로 배포하지 않고 `초안` 상태로 유지한다.

### 2.4. 문제 풀이 및 평가

평가 선택

#### 2.6.1. 공통 UI 상태 정의

모든 주요 화면은 다음 상태를 고려한다.

| 상태 | 표시 원칙 | 사용자 동작 |
|---|---|---|
| 초기/빈 상태 | 다음 행동을 설명하는 안내와 CTA 제공 | 등록 또는 생성 시작 |
| 로딩 | 현재 처리 단계와 예상 행동을 표시 | 필요 시 취소 |
| 성공 | 완료 내용과 다음 단계를 안내 | 결과 확인 또는 다음 단계 |
| 경고 | 작업은 가능하지만 확인할 내용을 표시 | 확인 후 계속 진행 |
| 오류 | 원인과 해결 방법을 가능한 범위에서 안내 | 재시도, 입력 수정, 문의 |
| 처리 중 | 장시간 작업의 진행 상태를 지속 표시 | 다른 화면 이동 허용 여부 결정 |
| 검토 필요 | 누락, 충돌, 낮은 신뢰도를 구분하여 표시 | 원문 비교, 수정, 승인 |
| 접근 불가 | 권한 또는 시스템 조건을 설명 | 이전 화면 이동 또는 권한 요청 |

## 3. 디자인 방향

### 3.1. 디자인 원칙

- 정보의 신뢰도와 처리 상태를 시각적으로 명확히 구분한다.
- 주요 작업은 한 화면에 하나의 우선 행동이 드러나게 구성한다.
- AI가 생성한 내용과 원문/사용자 입력을 구분한다.
- 색상만으로 상태를 전달하지 않고 아이콘과 텍스트를 함께 사용한다.
- 긴 문서와 표를 다루는 화면은 가독성과 탐색성을 우선한다.

### 3.2. 시각 디자인

| 항목 | 결정 내용 |
|---|---|
| 디자인 키워드 | 신뢰성, 안정감, 명료함, 자연스러움 |
| 컬러 시스템 | 녹색을 주조색으로 사용하고 밝은 중립색 배경과 짙은 회색 본문을 조합 |
| 주조색 | Primary `#15803D`, hover `#166534`, focus ring `#86EFAC` |
| 보조색 | 연한 녹색 배경 `#F0FDF4`, 선택 영역 `#DCFCE7`, 경계선 `#BBF7D0` |
| 상태색 | 성공은 녹색, 정보는 파랑, 경고는 주황, 오류는 빨강을 사용해 의미 충돌 방지 |
| 타이포그래피 | 한글 가독성이 높은 Sans-serif를 기본으로 하고 제목·본문의 위계를 명확히 구분 |
| 아이콘 | 선형 아이콘을 기본으로 하며 아이콘 옆에 의미를 설명하는 텍스트 병기 |
| 간격/그리드 | 8px 단위 간격 체계와 12열 데스크톱 그리드 사용 |
| 모서리/그림자 | 카드와 입력 요소는 8~12px 모서리, 낮은 단계의 그림자로 문서형 UI의 차분함 유지 |
| 다크 모드 | 1차 MVP에서는 제외하고 라이트 모드의 접근성과 인쇄 미리보기에 집중 |

녹색은 주요 버튼, 현재 단계, 선택 상태, 완료 상태에 집중하여 사용한다. 모든 영역을 진한 녹색으로 채우지 않고 흰색·연회색 여백을 충분히 두어 긴 문서를 읽을 때의 피로를 줄인다. 경고와 오류에는 녹색을 사용하지 않으며 색상 외에도 아이콘, 레이블, 안내 문구를 함께 제공한다.

### 3.3. 레이아웃 원칙

- 기본 콘텐츠는 데스크톱에서 최대 1440px를 기준으로 하되 문서 편집·미리보기 화면은 가용 너비를 확장한다.
- 좌측 전역 내비게이션은 240px를 기본으로 하고 편집 집중 모드에서는 축소할 수 있게 한다.
- 작성 마법사의 단계 표시기는 상단에 고정하여 현재 단계, 완료 단계, 남은 단계를 항상 확인할 수 있게 한다.
- 목차/내용 편집 화면은 `목차 트리 / 내용 편집 / 근거·보완 입력`의 3열 구조를 사용한다.
- PDF 화면은 `서식 설정 / 페이지 미리보기`의 2열 구조를 사용한다.
- 태블릿에서는 보조 패널을 서랍으로 전환하고, 모바일에서는 파일 등록·상태 확인·간단한 검토를 우선 지원한다.
- 주요 다음 단계 버튼은 화면 하단 작업 막대에 고정하고, 이전·임시 저장 동작을 함께 배치한다.
