2026-10-15에 근거 묶음 보완보다 스캔 PDF → 문제 → 점수 → 준비도·추천의 전체 흐름을
먼저 잇기로 했다.

1. [완료] 업무·인수자 SQLite 적재, Fit~Readiness 계산과 추천·분배 API
2. Gateway `generate_question` 기반 문제·정답·Rubric·근거 생성 → QuizScore로 준비도 확정
   ([설계안](plan/quiz-design.md): 원문 대조 검증, 절차 순서 문항부터)
3. LLM 답안 채점과 기존 Python 점수 비교 연결
4. 실제 문서 평가 결함 보완: 문장 잇기는 완료. 표 행 묶음, 페이지를 넘는 문장, 질문 조건 충족
   검증이 남음
5. 목차·내용 편집과 PDF 출력, 추천·평가 문항 화면

  게이트에 "정답 페이지 밖 발췌 증가 시 탈락" 항목을 추가했고, 첫 어댑터는 이 항목에서
  6→9로 탈락한다([학습 결과](training.md#게이트-판정)). 적용하지 않고 다음 학습에서 개선 권장
- 가상 업무 데이터 검토 목록, 40문항 정답 초안 확정

## 다음 단계에서 유지할 조건

- SQLite가 기준 저장소다. ChromaDB 내용만으로 근거가 유효하다고 판단하지 않는다.
- 현재 `page-lines-v1:chars=800` 결과는 기본 비교 기준으로 보존한다. 새 Layout 규칙은
  새 버전으로 만들며, 과거 생성 문서의 Chunk/Block ID를 삭제하거나 덮어쓰지 않는다.
- OCR/구조/색인/문서 생성의 완료 상태를 구분한다. 현재 **근거 준비됨**은 검색 가능 상태가 아니다.
- 현재 Chunk의 800자는 토큰 수가 아니다. 검색은 실제 토큰 길이로 창을 나누고
  정규화 벡터를 평균한다. 원문 Chunk를 수정하지 않으며 전처리 정책은 색인 버전에 포함한다.
- 근거 품질을 확인할 수 있는 최소 화면부터 연결하며 전체 작성 UI는 API가 준비되는 순서로 확장한다.
- 새 코드에는 기존처럼 역할, 호출 흐름, 예외/트랜잭션 이유를 설명하는 한국어 주석을 유지한다.

## 지난 상태 기록 (2026-10-13 기준)

아래는 당시 로드맵이다. 완료 여부는 위 현재 상태 표가 기준이다.

### 실제 문서 예비 평가 완료

제공된 PDF 8개·605페이지의 OCR/검색 색인과 40문항 실행을 마쳤다.
유답 32개는 초안 생성 15개·근거 없음 12개·시간 초과 5개, 무답 8개는 정상 거절 7개·
오선택 1개였다. 생성된 초안에서도 문장 잘림·숫자 오류가 확인돼 운영 품질 합격은 아니다.
[평가 결과와 결함별 후속 작업](evaluation.md#실제-문서-예비-평가-결과--2026-10-1213),
[재실행 방법](evaluation.md#실제-문서-예비-평가-실행)을 참고한다.

당시 다음 구현은 **문장/문단·표 행 단위의 근거 묶음과 질문 조건 충족 검증**이었다(2026-10-15에 5순위로 조정).
OCR Block ID와 과거 근거를 보존하는 새 구조 버전으로 구현하고 동일 실제 문항 및 기존
제어 문형 회귀 시험을 함께 비교한다. 정답 초안의 사용자 확정과 Layout 수동 정답은 남아 있다.

### 완료: 페이지 구조·Chunk·원문 근거

- OCR 완료 버전별 기본 Section과 Chunk를 생성하고 SQLite에 저장한다.
- 반복/동시 요청에서 동일 결과를 재사용한다. 도중 실패는 전체 롤백한다.
- 각 Chunk에서 원문 Block·페이지·이미지·좌표를 역추적한다.
- OCR 재처리 후 현재 목록과 과거 근거를 분리한다.
- 검토 화면에서 **근거 준비**와 페이지별 근거 강조를 제공한다.
- 기본 테스트 49개 통과, 실제 Edge 브라우저 검증 통과. 상세 규칙은
  [문서 구조와 근거 연결](pipeline.md#문서-구조chunk원문-근거-연결)에 정리했다.

### 추가 완료: 규칙 기반 Layout 분석

- `LayoutAnalyzer` 포트와 좌표 규칙 분석기, 제목 후보·본문·2단·표 후보·판별 보류 구현.
- 페이지 기본 결과와 새 parser_version의 배치 분석을 함께 보존한다.
- 화면에서 방식 선택, 검토 사유와 영역 강조를 제공한다.
- 한국어 Golden fixture 6종과 버전/저장/API/브라우저 검증을 추가했다.
- 실제 문서 정확도와 표 셀 복원은 미검증/미구현이다. 상세는 [배치 분석](pipeline.md#배치-분석과-검토) 참고.

### 다음 구현 순서와 완료 기준

Ollama 원문 발췌 초안의 Gateway·근거/검토 검증·작업 저장·API·화면을 연결했다.
모델은 원문 ID와 분류만 선택하고 본문은 SQLite에서 조립한다. 다운로드한 Qwen3-4B의
Transformers 직접 실행 경로를 추가했고 실제 GPU 추론을 검증했다. Ollama 실모델은
별도 미검증 상태다. 선택·분류 평가 범위와 한계는 [초안 생성 안내](search-and-draft.md#로컬-모델-원문-발췌-초안) 참고.

이전·실패 색인의 미리보기/선택 삭제와 실패·재시작 복구도 구현했다.
현재 OCR의 공개 색인과 실행 중인 작업은 보호하고 SQLite 원문·근거·검토 기록을 보존한다.
[이전 색인 정리 안내](search-and-draft.md#이전-검색-색인-정리) 참고.

실제 문서 평가를 위한 읽기 전용 OCR 내보내기, 수동 정답 계약, 순서·분류 지표와
HTML/JSON 보고서 도구도 추가했다. 합성 정답 6종으로 검증했으며 실제 업무 자료의
정답 작성과 평가는 아직 남아 있다. [배치 분석 평가 안내](evaluation.md#배치-분석-정답-평가) 참고.

페이지별 Layout 검토 상태·메모·확인 항목·이력과 전체 집계도 구현했다.
동시 편집 충돌과 OCR 버전 혼합을 차단하며 검색에 최신 검토 기록을 표시한다.
사용법은 [검토 기록 안내](pipeline.md#페이지별-배치-분석-검토-기록)를 참고한다.

ChromaDB 색인·검색은 완료했다. 로컬 모델 준비, 원자적 색인 공개, 실패/재시작 복구,
현재 OCR·구조·모델 버전 격리, 검색 근거와 검토 사유 및 원문 이동을 제공한다.
실행 방법과 검증 범위는 [검색 색인 안내](search-and-draft.md#로컬-검색-색인)를 참고한다.

| 순서 | 작업 | 시작할 내용 | 완료 기준 |
|---|---|---|---|
| 1 | 실제 문서 평가·교정 범위 확정 | 대표 문서 정답 구축, 저장된 수정 필요 메모에 따른 교정 요구 정리 | 실제 정답 대비 읽기 순서/제목/표 품질 기록; 표 셀 복원 범위 확정 |
| 2 | 검토·검색 품질 보완 | 필요 시 모델 기반 분석기, 텍스트/순서 교정 편집 | 수정 결과의 새 버전·과거 근거 보존 |
| 3 | 초안 품질 보완·확장 | 실제 자료 선택·분류와 제어 문형 규칙의 오탐·우회 평가 | 실제 정답에서 관련성/분류 측정; 원문 발췌 정책 유지 또는 검증 가능한 요약 정책 확정 |
| 4 | 목차·내용 편집과 PDF 출력 | 초안 저장/불러오기, 사용자 입력 출처, 수정본 revision 관리 | 새로고침 후 편집 복원; 확정 내용과 PDF 일치; 표/페이지 넘침 검수 |
| 5 | 평가 문항·답안 평가 | 확정 문서 기반 문제 생성, Rubric·근거 검증, 기존 점수 비교 엔진 연결 | 문제 검토 후 확정; 답안 채점 및 차이 검토; 인수자 결과 저장/조회 |

실제 자료의 예비 평가 기준선은 확보했다. 전체 페이지의 읽기 순서·영역 정답은 없어
Layout 정확도 자체는 미측정이다. 합성 자료 결과와 실제 자료 결과는 별도로 기록한다.

새 자료를 추가할 때 파일 위치와 작성 예시는 [실제 문서 평가 준비](evaluation.md#실제-업무-문서-평가-준비)를
참고한다. 기존에 제공한 8개 PDF와 40문항을 다시 준비할 필요는 없다.

Qwen은 명시적 제어 문형 차단과 선택 원문별 독립 관련성 검증을 결합했다. v9는
기존 회귀 15종과 새 4종, 총 19/19를 통과했고 v6의 판정 강요·관리자 사칭 실패도 보완했다.
이는 모델 단독 성능이나 모든 우회에 대한 보장이 아니다. 알려지지 않은 표현과 규칙의
오탐은 실제 문서로 계속 평가해야 한다. 명령형 업무 절차를 일괄 차단하거나 자동 승인하지 않는다.
