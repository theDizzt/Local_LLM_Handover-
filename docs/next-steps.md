# 다음 작업 계획

2026-10-05 기준. 아래 순서는 현재 구현의 의존 관계를 기준으로 정했다.

## 이번에 완료한 단계: 페이지 구조·Chunk·원문 근거

- OCR 완료 버전별 기본 Section과 Chunk를 생성하고 SQLite에 저장한다.
- 반복/동시 요청에서 동일 결과를 재사용한다. 도중 실패는 전체 롤백한다.
- 각 Chunk에서 원문 Block·페이지·이미지·좌표를 역추적한다.
- OCR 재처리 후 현재 목록과 과거 근거를 분리한다.
- 검토 화면에서 **근거 준비**와 페이지별 근거 강조를 제공한다.
- 기본 테스트 49개 통과, 실제 Edge 브라우저 검증 통과. 상세 규칙은
  [문서 구조와 근거 연결](document-structure.md)에 정리했다.

## 추가 완료: 규칙 기반 Layout 분석

- `LayoutAnalyzer` 포트와 좌표 규칙 분석기, 제목 후보·본문·2단·표 후보·판별 보류 구현.
- 페이지 기본 결과와 새 parser_version의 배치 분석을 함께 보존한다.
- 화면에서 방식 선택, 검토 사유와 영역 강조를 제공한다.
- 한국어 Golden fixture 6종과 버전/저장/API/브라우저 검증을 추가했다.
- 실제 문서 정확도와 표 셀 복원은 미검증/미구현이다. 상세는 [배치 분석](layout-analysis.md) 참고.

## 다음 구현 순서와 완료 기준

Ollama 원문 발췌 초안의 Gateway·근거/검토 검증·작업 저장·API·화면을 연결했다.
모델은 원문 ID와 분류만 선택하고 본문은 SQLite에서 조립한다. 실제 Ollama 서버·모델이
없어 실모델 추론은 아직 검증하지 않았다. [초안 생성 안내](draft-generation.md) 참고.

이전·실패 색인의 미리보기/선택 삭제와 실패·재시작 복구도 구현했다.
현재 OCR의 공개 색인과 실행 중인 작업은 보호하고 SQLite 원문·근거·검토 기록을 보존한다.
[이전 색인 정리 안내](search-cleanup.md) 참고.

실제 문서 평가를 위한 읽기 전용 OCR 내보내기, 수동 정답 계약, 순서·분류 지표와
HTML/JSON 보고서 도구도 추가했다. 합성 정답 6종으로 검증했으며 실제 업무 자료의
정답 작성과 평가는 아직 남아 있다. [배치 분석 평가 안내](layout-evaluation.md) 참고.

페이지별 Layout 검토 상태·메모·확인 항목·이력과 전체 집계도 구현했다.
동시 편집 충돌과 OCR 버전 혼합을 차단하며 검색에 최신 검토 기록을 표시한다.
사용법은 [검토 기록 안내](layout-review.md)를 참고한다.

ChromaDB 색인·검색은 완료했다. 로컬 모델 준비, 원자적 색인 공개, 실패/재시작 복구,
현재 OCR·구조·모델 버전 격리, 검색 근거와 검토 사유 및 원문 이동을 제공한다.
실행 방법과 검증 범위는 [검색 색인 안내](search-indexing.md)를 참고한다.

개인정보 없는 제목·표·다단 fixture를 준비하여 Layout 개발을 진행할 수 있다.
합성 자료 결과와 실제 자료 결과는 별도로 기록한다.

## 다음 단계에서 유지할 조건

- SQLite가 기준 저장소다. ChromaDB 내용만으로 근거가 유효하다고 판단하지 않는다.
- 현재 `page-lines-v1:chars=800` 결과는 기본 비교 기준으로 보존한다. 새 Layout 규칙은
  새 버전으로 만들며, 과거 생성 문서의 Chunk/Block ID를 삭제하거나 덮어쓰지 않는다.
- OCR/구조/색인/문서 생성의 완료 상태를 구분한다. 현재 **근거 준비됨**은 검색 가능 상태가 아니다.
- 현재 Chunk의 800자는 토큰 수가 아니다. 검색은 실제 토큰 길이로 창을 나누고
  정규화 벡터를 평균한다. 원문 Chunk를 수정하지 않으며 전처리 정책은 색인 버전에 포함한다.
- 근거 품질을 확인할 수 있는 최소 화면부터 연결하며 전체 작성 UI는 API가 준비되는 순서로 확장한다.
- 새 코드에는 기존처럼 역할, 호출 흐름, 예외/트랜잭션 이유를 설명하는 한국어 주석을 유지한다.
