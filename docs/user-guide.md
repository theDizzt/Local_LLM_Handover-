# 사용자 안내: 실행·검토·자료 준비

2026-10-13 확인 기준. 앞으로 개발할 기능이 아니라, 현재 준비된 프로그램을 사용하고
실제 업무 자료로 검증하기 위해 사용자가 해야 할 일을 정리했다.

## 1. 지금 필요한 작업: 실제 자료와 정답 준비

**자료 준비와 첫 평가 실행은 완료했다.** 제공한 8개 PDF·40문항을 다시 만들 필요 없다.
[실제 평가 결과](evaluation.md#4-실제-문서-예비-평가-결과-2026-10-1213)를 확인하고, 정답 초안의 원문 인용과
업무상 정답을 최종 검토하면 된다. 아래 자료 준비 항목은 새 문서를 추가할 때 적용한다.

현재 가장 필요한 것은 대표 업무 PDF와 사람이 확인한 정답이다.
자료를 준비하고 경로를 알려 주면 OCR·색인·모델 평가 실행과 보고서 정리는 개발 작업으로 요청할 수 있다.
아래 프로그램 사용 절차를 모두 직접 수행해야 하는 것은 아니다.

- [ ] 대표 PDF **2~3개**를 `data/evaluation-input/`에 넣거나 기존 저장 경로를 알려 준다.
- [ ] 가능하면 본문 위주 문서와 표 또는 스캔 문서를 포함한다.
- [ ] 문서마다 **질문 3~5개**와 **정답 페이지·원문 문장**을 작성한다.
- [ ] 문서마다 **답이 없는 질문 1개**도 추가하고 `문서에 없음`이라고 적는다.
- [ ] 여러 문장이 정답이면 해당 페이지와 문장을 모두 적는다.

자료 폴더의 전체 경로:

```text
C:\Github\Local_LLM_Handover-\data\evaluation-input\
```

PDF를 이 폴더에 넣는 것만으로 앱에 자동 등록되지는 않는다.
직접 사용할 때는 화면에서 등록하고, 평가를 맡길 때는 파일 경로를 알려 주면 된다.
평가에 필요 없는 민감 정보는 제외한다.

정답은 `data/evaluation-input/answers.md` 같은 일반 Markdown 파일로 작성하면 된다.
Block ID나 프로그램용 JSON을 직접 작성할 필요는 없다.

```text
파일: 운영절차.pdf
질문: 장애가 발생하면 누구에게 연락하나요?
정답 페이지: PDF의 3번째 페이지
정답 원문: 장애 발생 시 운영 담당자에게 연락한다.
분류: 문제 해결

파일: 운영절차.pdf
질문: 출장비 지급일은 언제인가요?
정답: 문서에 없음
```

분류는 `개요 / 사전 조건 / 절차 / 주의사항 / 문제 해결` 중 선택한다.
페이지 번호는 인쇄된 쪽수와 혼동하지 않도록 **PDF에서 몇 번째 페이지인지** 적는다.
자세한 준비 방법은 [평가 > 실제 문서 평가](evaluation.md#3-실제-문서-평가-준비실행)를 참고한다.

## 2. 이미 준비되어 있어 다시 할 필요 없는 작업

현재 작업 PC에서는 다음 준비와 검증을 마쳤다.

| 항목 | 준비 상태 |
|---|---|
| Qwen3-4B | `data/models/Qwen3-4B`에 저장, 실제 GPU 추론 확인 |
| 검색 모델 E5 | `data/models/multilingual-e5-small`에 저장, 검색 연동 확인 |
| 한국어 OCR 모델 | 아래 실행 명령에 사용하는 로컬 모델 폴더 존재 확인 |
| 실행 환경 | 현재 `.venv`에서 프로그램 및 테스트 실행 확인 |
| 초안 처리 | 검색·원문 선택·관련성 확인·초안 저장·제외 이력 기록 구현 |

현재 PC에서 다시 모델을 다운로드하거나 Ollama를 추가 설치할 필요는 없다.
새 PC로 옮기거나 모델 폴더를 변경할 때만 환경을 다시 확인하면 된다.
합성 자료 검증 완료는 실제 업무 문서의 정확성 검증 완료를 뜻하지 않는다.

## 3. 직접 사용할 때: 프로그램 실행

PowerShell에서 다음 명령을 실행한다. 현재 있는 OCR 모델을 지정하므로 첫 OCR 실행에서
모델을 다시 다운로드하려는 동작을 피할 수 있다.

```powershell
Set-Location 'C:\Github\Local_LLM_Handover-'
$env:PADDLE_PDX_CACHE_HOME = "$PWD/data/ocr-validation/models"
$env:OCR_DETECTION_MODEL_DIR = "$PWD/data/ocr-validation/models/official_models/PP-OCRv5_mobile_det"
$env:OCR_RECOGNITION_MODEL_DIR = "$PWD/data/ocr-validation/models/official_models/korean_PP-OCRv5_mobile_rec"
.\run-qwen.bat
```

- [ ] 서버가 실행되면 브라우저에서 `http://127.0.0.1:8000/`을 연다.
- [ ] 작업하는 동안 서버 터미널을 열어 둔다. 종료할 때는 `Ctrl+C`를 누른다.

`run-qwen.bat`은 Qwen 제공자·모델 경로·120초 제한을 설정한다.
위 OCR 환경 변수는 해당 PowerShell 창에서 유효하므로 새 창에서는 다시 설정한다.
`.env.example`은 참고 파일이고, `.env` 파일을 수정하는 것만으로는 설정이 적용되지 않는다.
현재는 서버 한 개로 사용하며 `--workers`를 추가하지 않는다.

## 4. 직접 사용할 때: 문서별 확인 절차

| 순서 | 사용자가 할 일 | 확인할 내용 |
|---|---|---|
| 1 | PDF 선택 후 **PDF 등록** | 원하는 파일인지 확인. 암호화 PDF는 사용할 수 없음 |
| 2 | **OCR 시작** | 완료 후 원문 이미지와 인식 텍스트 대조 |
| 3 | **배치 분석 (시험)** 선택 후 **근거 준비** | 제목·본문·표 후보와 읽기 순서 확인 |
| 4 | 페이지별 검토 저장 | 텍스트·순서·영역을 확인하고 **검토 완료 저장** |
| 5 | **검색 색인 준비·재구축** 후 검색 | 업무 질문으로 검색하고 결과의 원문 위치 확인 |
| 6 | **근거 기반 인수인계 초안** 생성 | 제목·질문을 입력하고 기본 검토 완료 근거 사용 옵션 유지 |
| 7 | 생성된 초안 재검토 | 관련성·분류·누락·숫자·절차 순서를 원문과 비교 |

검토할 때 특히 확인할 항목:

- [ ] 이름·연락처·시간·수량 등 중요한 문자열이 OCR에서 바뀌지 않았는지 확인한다.
- [ ] 표의 행·열이나 다단 문서의 읽기 순서가 섞이지 않았는지 확인한다.
- [ ] 문제가 있으면 **수정 필요 저장**을 누르고 페이지와 문제 내용을 메모한다.
- [ ] 초안의 문장별 원문 링크를 열어 실제 근거와 맞는지 확인한다.
- [ ] 원문 제외 안내가 있으면 필요한 업무 내용까지 빠졌는지 확인한다.

검토 완료나 수정 필요 메모를 저장해도 OCR 텍스트 자체가 수정되지는 않는다.
현재 화면은 검토 기록을 저장하는 기능이며 텍스트·표를 직접 고치는 편집기는 아직 없다.
오류가 있으면 해당 문서·페이지·잘못된 문장·올바른 문장을 알려 주면 된다.

초안은 원문 발췌형이며 자동 승인되지 않는다. 명시적인 모델 제어 지시 문형에 해당하는
블록은 제외되며, 업무 내용과 해당 문형이 한 블록에 섞이면 함께 제외될 수 있다.
실제 업무에 쓰기 전 사람의 내용 확인이 필요하다.

## 5. 문제가 생겼을 때만 할 일

| 상황 | 할 일 |
|---|---|
| OCR 모델을 읽지 못함 | 위 로컬 모델 경로를 확인하고 환경 변수를 설정한 창에서 서버를 다시 실행 |
| 적격 근거가 없음 | 배치 분석의 페이지 검토를 완료했는지 확인. `수정 필요` 페이지는 초안에서 제외됨 |
| 관련 근거가 없음 | 문서에 실제 답이 있는지 확인하고 질문을 구체화. 답이 있다면 페이지·원문을 전달 |
| 모델 시간 초과 | 작업 오류를 확인하고 재시도. 반복되면 질문·문서명·오류 표시를 전달 |
| 검토 저장 충돌 | 작성한 메모를 보관한 뒤 최신 검토 상태를 다시 불러오고 저장 |
| OCR 재처리 또는 구조 방식 변경 | 현재 버전의 근거·검토 상태·검색 색인을 다시 확인 |

디스크 정리가 필요할 때만 화면의 이전 색인 목록을 확인하고 삭제할 항목을 선택한다.
사용을 시작하기 위해 색인을 미리 삭제할 필요는 없다.

## 6. 자료 준비 후 알려 줄 내용

아래 내용만 전달하면 다음 평가를 이어서 진행할 수 있다.

```text
PDF 위치: data/evaluation-input/
정답 파일: data/evaluation-input/answers.md
가장 중요하게 확인할 부분: 예) 연락처와 장애 대응 순서, 표의 행·열 대응
이미 발견한 문제: 예) 운영절차.pdf의 PDF 3번째 페이지에서 숫자 누락
```

개발용 테스트 실행, 평가 보고서 생성, Block ID 연결은 직접 할 필요 없다.
사용자는 **실제 자료 제공, 업무상 정답 판단, 결과의 업무 적합성 확인**을 맡으면 된다.
